## 1. 报文架构(Packet.cs)

### 1.1 MessageID 自动生成

- 所有包继承 `LibraryCore/Network/Packet.cs` 的抽象 `Packet`;
- `Packet` 静态构造(Packet.cs:10)扫描当前程序集所有 `Packet` 子类(Packet.cs:22-48):按**(命名空间, 类名)排序,GeneralPackets 优先**,排序后的下标即 **Int16 MessageID**;
- **无显式 MessageID 常量。新增/删除包类会改变后续所有 ID**——客户端与服务端必须同步编译,否则错位解析。

### 1.2 序列化(反射)

- 发送 `GetPacketBytes()`(Packet.cs:151):`Packets.IndexOf(GetType())` 写 2 字节 ID,反射遍历所有 public 属性序列化(WriteObject, Packet.cs:202);枚举按底层整数,Color/Point/TimeSpan/DateTime 有专用编码;List/字典/嵌套类递归处理;
- 接收 `ReceivePacket`(Packet.cs:133):按 ID 实例化再反射反序列化(ReadObject);
- `[CompleteObject]`:标记的方法在客户端反序列化后补全引用字段(如 `MagicLeveled.Info` 按 InfoIndex 查 MagicInfo、`NPCResponse.Page`、`DataObjectMonster.MonsterInfo`、`DataObjectItem.ItemInfo`、`GuildConquestDate.WarDate`);
- `[IgnorePropertyPacket]`:跳过该属性不序列化;
- `ObserverPacket` 基类属性(Packet.cs:18):控制观战者是否收到该包。

### 1.3 网络帧格式

```
[4 字节长度头][2 字节 MessageID][反射序列化的属性字节流]
```

### 1.4 收发链路

```
服务端: PlayerObject/MonsterObject 逻辑 → Broadcast(p) 或 Player.Enqueue(p)
   → PlayerObject.Enqueue(Packet) = Connection.Enqueue(p) (PlayerObject.cs:16625)
   → SConnection 发送队列 → 网络线程 GetPacketBytes 写出
客户端: CEnvir 网络线程 → Packet.ReceivePacket 按 ID 实例化 → CConnection.Process(S.*)
```

- `SEnvir.Broadcast(Packet)`(SEnvir.cs:4128):全服广播(遍历 Players.Enqueue);
- 对象级 `Broadcast(p)`:广播给视野内所有玩家(带距离过滤);
- 命名约定:`S.ObjectXxx`=世界实体动作广播;`DataObjectXxx`=小地图/好友视野数据;`NPCSocket*/Refine*/Craft`=打造系统;`Mail*/MarketPlace*/GameStore*`=交易;`Companion*`=伴侣;`Guild*`=行会;`Quest*`=任务;另有 `G.*`(GeneralPackets,如 G.Disconnect)双向。

## 4. 代表双向链路(端到端示例)

### 4.1 玩家移动(最频繁的包)

```
客户端: MapControl.ProcessInput → AttemptAction(Moving) → CEnvir.Enqueue(new C.Move{Direction, Distance})
  → SConnection.Process(C.Move)(427) → PlayerObject.Move(14494)
    → 碰撞校验(IsBlocking 逐格) → 移除隐身 → Broadcast(S.ObjectMove{Direction, Location, Distance, Slow})
      → 客户端 CConnection.Process(S.ObjectMove)(1001)
        → 自己: Displacement + NextActionTime += Slow
        → 别人: ActionQueue 入 ObjectAction(Moving, dir, loc, Slow, Distance) → Walking/Running 插值
```

### 4.2 玩家施法

```
客户端: GameScene.UseMagic(3304) → 校验/锁定目标 → AttemptAction(Spell) → C.Magic{Direction, Action=Spell, Type, Target, Location}
  → SConnection.Process(C.Magic) → PlayerObject.Magic(14731) → ServerLibrary/Models/Magics/<Class>/<Skill>.cs
    → 结算伤害 + Broadcast(S.ObjectMagic{Type, Targets, Locations, Cast=true}) 或 S.ObjectAttack(近身技能如 DanceOfSwallow:77)
      → 客户端: 别人播 Spell 动画 + MagicType 特效;自己同样播(双重确认)
```

### 4.3 怪物施法(服务端主动)

```
MonsterObject.ProcessAI → ProcessTarget → AttackMagic/AttackAoE/LineAoE
  → Broadcast(S.ObjectMagic{Cast=true, Type, Targets/Locations}) + DelayedAction(500ms+距离×48, DelayAttack)
    → 客户端 SetAction Spell: Combat3 + MagicType 特效(MonsterScortchedEarth 三重复合地板等)
    → 延迟结算伤害 → HealthChanged 飘字
```

### 4.4 登录全流程(SEnvir.cs:3276-3396)

```
C.Login → SEnvir 校验 → S.Login(失败分支 3276/3282/3288/3303/3309/3317/3340/3352/3362/3377/3381;成功 3396 带角色列表)
```

## 5. 要点与坑

1. **无显式 MessageID**:排序索引自动生成,增删包类会平移后续 ID,两端必须同步编译;
2. **纯确认/触发空包**:SelectLogout, TradeClose, TradeUnlock, NPCClose, CombatTime, MailSend, GuildTax, GuildCreate 等(只带 MessageID);
3. **观战**:`ObserverPacket` 基类属性控制是否发给观战者;
4. **[CompleteObject] 补全型字段**:MagicLeveled.Info, MagicCooldown.Info, NPCResponse.Page, DataObjectMonster.MonsterInfo, DataObjectItem.ItemInfo, GuildConquestDate.WarDate;
5. **世界对象包统一模式**:`ObjectID + Direction + Location (+ Slow 时间戳)`,客户端据此驱动 MirAction 动画;Slow 是动作时间戳,客户端 `NextActionTime += Slow` 对齐两端节奏;
6. **动作类 C.* 与 S.* 一一对应**:C.Move↔S.ObjectMove, C.Attack↔S.ObjectAttack, C.Magic↔S.ObjectMagic, C.Harvest↔S.ObjectHarvest, C.Mining↔S.ObjectMining, C.FishingCast↔S.ObjectFishing, C.Taming↔S.ObjectTaming,C.Turn↔S.ObjectTurn——**客户端动作请求与服务端动作广播成对出现,这是"双端确认"协议的核心**;
7. **服务端处理器共 152 个**(SConnection.cs),均先校验 `Stage == GameStage.Game` 与方向范围再委托 `Player.X`。
