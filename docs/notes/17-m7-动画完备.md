# 17 · M7 动画完备（通用对象动画运行时）

> 里程碑 M7：让怪物 / NPC / 地面物品的动画"真正会动"——走路平滑、动画按原版节奏播放、动作可排队切换。
> 对应原版 `Client/Models/MapObject.cs` 的 `UpdateFrame / SetFrame / DoNextAction`。

## 之前的问题（M5/M6 留下的）

- 帧推进是**自己手写**的简单时钟：固定每帧 100ms 从头到尾走一遍，没有原版的双倍速、倒放、固定速度概念。
- 怪物走路是**格子级跳跃**：先把当前位置四舍五入到格子，再从起点格跳到终点格，画面上一格一格地"跳"，不是平滑移动。
- 动作之间**没有队列**：播完攻击动画就硬切回站立，无法连续攻击、无法被新动作打断。
- 没有帧号变化钩子、没有缩放能力。

## 这次做了什么

### 1. 帧推进换成原版 `Frame.GetFrame` 语义（MapObjectNode.cs）

原版每个动画帧表 `Frame` 自带 `Delays`（每帧停留时长）、`Reversed`（倒放）、`StaticSpeed`（固定速度，不受加速影响）。

新实现的 `GetFrameIndex(nowMs, doubleSpeed)`：

- **双倍速**：当对象有 2 个以上排队动作时，播放时间翻倍（跑步、连续动作更快，与原版一致；`StaticSpeed` 帧不受影响）。
- **倒放**：`Reversed` 帧表从最后一帧往前播（原版某些技能/特效用）。
- **播完返回"动画结束"标记**：由外层决定收尾（弹下一个动作或停在最后一帧），不再自己硬夹到最后帧。

### 2. 移动改成"权威格 + 8 向像素偏移"（原版 MovingOffSet）

原版移动时，服务端权威格子**立即**更新到终点格，画面位置靠一个"从终点往回拉"的像素偏移来表现"正在从起点走过来"。

- 起点 → 终点按 8 个方向（上/右上/右/右下/下/左下/左/左上）计算偏移；
- 偏移随时间从"整格距离"衰减到 0，斜向走直线、多格移动按距离比例走，全部平滑；
- 像素偏移做**偶数对齐**（原版 `x -= x % 2`），避免动画抖动；
- 移动动画播完（`Walking` 帧表走完）自动落格并回到站立。

验证日志（真实运行数据，Chicken 向左走 1 格，每帧 100ms、共 6 帧）：

| 帧号 | 理论偏移 | 实测偏移 |
|---|---|---|
| frame 0 | -48 × 0.875 ≈ -42 | (-42, 0) |
| frame 2 | -48 × 0.625 ≈ -30 | (-30, 0) |
| frame 4 | -48 × 0.29 ≈ -14 | (-14, 0) |

另有一只鸡从 (154,233) 走到 (152,233)（2 格），起步帧偏移 (-94, 0) ≈ 2 格 × 48 × 0.98，多格移动正确。

### 3. 动作队列（原版 ActionQueue + DoNextAction）

- `SetAnimation`：立即切换动画；站立/死亡会**打断**当前动作，其他动作**播完再切**（原版 `Interupt` 规则）。
- `QueueAction`：把动作排进队列（用于连续攻击等）。
- `DoNextAction`：当前动画播完或被中断时，弹队列里的下一个动作；队列空则回到站立（死亡后保持死亡姿态）。
- 动画播完若没有下一个动作，**停在最后一帧**（原版 `frame -= 1`），不再跳回第 0 帧。

### 4. 钩子与缩放

- `FrameIndexChanged()`：帧号变化时调用的虚方法（原版 5172 行），供后续里程碑挂攻击/受击/死亡音效与特效（现在先留空）。
- `SetScale(sizePercent)`：按原版公式 `(100 + 限制在 ±50)/100` 缩放对象，原版用于怪物大小差异（`ObjectMonster.SizePercent`）。

### 5. 配套改动

- `GameScene.UpdateObjectPositions` 改为调用 `MapObjectNode.ComputeScreenPos`（自带像素偏移），否则每帧刷新位置会把移动偏移覆盖掉。

## 验证结果

- `dotnet build GodotClient/ZirconClient.csproj` → **0 错误**。
- headless 回归（`timeout 40 godot-mono --headless -- --auto-login`）：进入游戏、添加 34 个物体、**0 异常、0 断连**（exit=124 为超时正常）。
- 窗口运行 + 游戏内截图（/tmp/m7_win*.png，inspect_image 确认）：
  - 画面正常渲染，无黑屏花屏；
  - 有怪物处于**行走姿态、格子间偏移**位置（与静止单位明显错位）；
  - 日志证实 8 向偏移、多格移动、帧推进全部按公式工作。

## 关键决策

1. **双倍速条件简化为 `ActionQueue.Count > 1`**：原版是 `(this != User || Observer) && ActionQueue.Count > 1`；本客户端玩家走 PlayerRenderer，周围物体恒非 User，故等价。
2. **移动采用原版平滑分支（时间比例）**：`t = min(已播放时长 / 动画总时长, 1)`，与帧推进共用同一时钟，不会出现帧和位置不同步。
3. **权威格立即到终点 + 偏移回拉**：这是原版正统做法；中途被打断（如受击）时对象已经落在权威位置，不会"悬在途中"。
4. **留 `FrameIndexChanged` 空钩子**：M10/M16 的音效、M13 的技能特效会挂到这里，现在不提前实现。
