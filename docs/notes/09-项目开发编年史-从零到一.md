## 0. 项目是什么

Zircon 是**传奇 3（Legend of Mir 3）的 C# 服务端 + 客户端**模拟器。原仓库 `Suprcode/Zircon`，社区在 LOMCN 论坛（`lomcn.org`）。传奇 3 是韩国 Wemade 2002 年推出的网游，在中国由光通代理运营，是一代中国玩家的记忆——这解释了后文为什么会有中国开发者来给它做中文翻译。

本仓库是 fork（`iamcheyan/Zircon`），我们的目标是用 Godot 重写跨平台客户端连接原版服务端（见笔记 01-06）。

## 2. 第一章 2019：诞生（55 条提交）

**一句话**：AndyF 把一个 Mir3 私服模拟器代码库导入 GitHub，开局就带图库编辑器，七个月里吸引 7 位贡献者。

### 2019-02 起点（10 条）

- `1647f9e` **2019-02-01 初始提交**（AndyF）："Initial Commit Added Visual companion equipment"。代码库最初是**已能运行的完整模拟器**（服务端 + 客户端 + 编辑器），不是空壳——带视觉伴侣装备功能。同日 `f75d264` 创建 README。
- `352f818` **2019-02-03 Library Editor**（AndyF）：图库编辑器登场——这是整个资产管线的核心工具，负责读写 .Zl/.WTL 图库。同周 Lilcooldoode 连续修它：`b724d8b` 修复 .zircon 文件保存、`9663d84` 动画对象混合、`c298170` 转换修复、`44702f0` 重试修复。
- `4600ed4`/`d97bf90`/`40b28b1`（AndyF）：可见盾牌 + 女角色盾牌偏移修复。

### 2019-02/03 第一批贡献者（8 条）

- **Carl Brand**（PR #2、#3，并入 develop 分支）：`4a4964c` 生成怪物命令、`102edad` 创建公会命令、`7c6914d` 修伴侣在背包满时不捡金币。
- **Pete107**（PR #7）：`919d2d5` 库编辑器支持直接打开 .ZI 文件、改输出文件名。
- **Lilcooldoode**：`77e620b` 大师精炼（Master refine）漏洞利用修复、`1076ab0` 服务器崩溃定位。

### 2019-05/07 装备与仓库（8 条）

- **LionsMight1**（PR #12、#16、#17）：`9b0fde2` Mir3 配件系统（Accessory）、`6cf50f1` 仓库部件页签（Parts Storage Tab）、`161afdc` 主部件修复。配件系统是传奇 3 特色——翅膀、时装、坐骑都挂在这里。

### 2019-08 Ryan Taplin 的经验表改造（14 条）

Ryan Taplin 用 14 条提交一口气做"可配置经验表"（ConfigExperienceList）：从服务端 `SEnvir.Load`、`PlayerObject` 到客户端 `GameScene`、经验条、排行，全链路支持配置文件控制经验曲线——把原来写死的经验数值变成可调配置。

### 2019-09/12 收尾（5 条）

- LionsMight1：`e33267a` 基础属性查看器（Base Stats Viewer）。
- Bernat Vadell：`207134f` **支持 ILIB v2.0（WEMADE 官方图库格式）**——让模拟器能读官方客户端资产，这是 2019 年最重要的资产兼容性突破。
- Pete107 修 `SEnvir.cs`、LionsMight1 修账户包轰炸漏洞（#23）。

**本章关键词**：图库工具、配件系统、经验配置化、官方资产格式支持。项目从"能跑"走向"有工具链"。

## 10. 尾声：这个项目教会我们什么

1. **一个人可以撑起一个项目 7 年**：AndyF/Suprcode 81.5% 的提交占比，从图库工具到渲染引擎全部亲力亲为。私服模拟器是"热爱驱动"的典型——没有商业 KPI，只有"让玩家玩得爽"。
2. **架构决策的复利**：2020 年 .NET Core 迁移当时只是"跨平台"，7 年后让我们能在 Linux 上跑起 ServerCore。**今天看似无关的决策，可能是三年后的地基。**
3. **社区是内容的来源**：翻译（中国）、武器（Lanaya）、音频格式（phoenixvdp）、多语言架构（Shào）——核心代码之外，玩法与本地化全部来自社区。
4. **技术栈始终跟随时代**：.NET Framework → .NET Core → .NET 7 → .NET 8 → .NET 10；SlimDX → SharpDX → 自研 DX9/DX11 → Vulkan/SilkNet。一个 2019 年的项目到今天仍能编译运行，靠的是持续升级。
5. **我们的位置**：我们 fork 的是 2026-07 的最新状态（#261），上游仍在活跃开发。Godot 客户端重写是对"Windows 钉死"的最后一次反叛——作者用 Vulkan/SilkNet 留在 Windows 生态，我们用 Godot 走向全平台。

### 11.2 两位开发者：Jamie 与 Far

论坛板块的官方标注写着 **"Developers: Jamie, Far"**。

- **Far** = 另一位开发者，长期活跃：2021-12-28 发 *"NEW Mir 3 Map Editor"*（**88 回复，板块第二热帖**，专门给 Mir 3 做新地图编辑器）；还有 "Zircon Autopatch Client"、"Event Info system enhancements" 等开发帖。Far 在 git 中对应哪个身份未证实，但**地图编辑器**这条线贯穿了社区始终——从 2019-02 "Doubts to add new maps"、2020-05 "Is there a map editor for mir3"、2020-06 "Any guides on getting mir2 maps working on zircon?"（48 回复）、2022-05 "add new map question"，一直到 2025-08 还有人问 "Looking for help/guide on how to get mir2 maps into zircon"。**地图，是 Zircon 社区七年的头号痛点**——这正好是我们 fork 里 `.Zl/.map 读取器`（提交 0440548）的价值所在。

### 11.3 跨平台的种子（2019-12-14）

2019 年 12 月 14 日，用户 **ElAmO** 发 *"Crossplatform support"*——讨论把服务端迁到 .NET Core 实现跨平台（76 回复，当年第三热帖）。12 月 28 日又发 *"Mobile Joystick Virtual"*（移动端虚拟摇杆）。

四个月后，git 里出现了 **Bernat Vadell 的 .NET Core 大迁移**（#31，2020-04/05，15 条提交，见 §3）。ElAmO 与 Bernat 是否同一人未证实（邮箱不可比对），但叙事线很清晰：**论坛先有呼声，代码后有落地**。

这条线一直延伸：ElAmO 的移动端摇杆 → 2022-03 tianshi97 发 *"ZirconMir3MobileGameSource"* → 2025-04 mull 发 *"Zircon Mir3 Mobile Source"*（12 回复）→ 2026-05 dwaring28720 发 *"Unity Zircon Client"*（用 Unity 重写客户端，7 回复）。**我们不是第一个重写客户端的——但我们是第一个用 Godot 的**（见 §9.4）。
