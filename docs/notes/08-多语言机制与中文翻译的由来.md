# 讨论记录 08：多语言机制与中文翻译的由来

> 日期：2026-08-06
> 关联：讨论 01~06 聚焦架构与渲染；本篇回答"客户端/服务端如何做本地化、数据是否多语言、切换机制"，并挖出中文翻译的 git 历史——这是一段"接口先预留、社区再填满"的开发者故事。
> 结论：**UI/系统消息层是真正的多语言架构（英中双语文档齐备、运行时切换）；游戏世界数据（物品/怪物/NPC/对话）是英文单语言硬编码在 System.db，没有多语言接口。中文是"官方第二语言"：接口由作者 2019 年预留，翻译由中国开发者 2024 年补到 100%。日文不存在，要加需动 4 处代码。**

---

## 1. 三层文本，语言机制各不相同

把游戏里出现的所有文字分成三层，每层的语言能力和存放位置完全不同：

| 层 | 文本内容 | 存放位置 | 语言 | 多语言？ |
|---|---|---|---|---|
| ① UI + 系统消息 | 按钮、提示、战斗消息、命令回复 | `Client/Envir/Translations/` + `ServerLibrary/Envir/Translations/`（各一套） | 英 + 中 | ✅ 完整，运行时切换 |
| ② 游戏世界数据 | 物品/怪物/NPC/魔法/地图/任务**名称** | `System.db` 各 Info 表，单一 `Name` 字段 | 英文 | ❌ 单语言 |
| ③ NPC 对话 | "Drugs, Get your Drugs here…" | `System.db` 的 `NPCPage.Say` | 英文 | ❌ 单语言 |

关键认知：**"中文"只覆盖第①层**。切到中文后，按钮、系统消息、战斗提示是中文，但所有物品名、怪物名、NPC 名字和对话依然是英文——因为它们在数据库里。

## 2. 双语机制怎么工作（源码证据）

```
StringMessages（抽象基类，客户端 757 条抽象属性 / 服务端 313 条）
  ├── EnglishMessages   ← 实现（757 / 313 override）
  └── ChineseMessages   ← 实现（757 / 313 override，中文覆盖 100%）
```

- **翻译类**：`Client/Envir/Translations/` 与 `ServerLibrary/Envir/Translations/` 各有一份三件套。中英文案 100% 覆盖，无缺漏。
- **选择逻辑**：
  - 客户端 `CEnvir.LoadLanguage()`（`Client/Envir/CEnvir.cs:96` 附近）按 `Config.Language` 在 `ENGLISH` / `CHINESE` 间二选一；
  - 服务端 `SConnection.cs:48` 默认英文，收到客户端发的 `C.SelectLanguage` packet 后**按连接**切换（`SConnection.cs:253`）。
  - 两端 switch **都没有 default** —— 未知语言时服务端静默回落英文，客户端 `CEnvir.Language` 变 `null` 后续 UI 会空引用崩溃。
- **语言跟随连接，不跟随服务器**：没有"服务器语言"全局设置。登录时客户端主动上报（`CConnection.cs:154`），服务端按**每个玩家各自的**语言发消息——组队时"队长用中文喊、队友用英文听"是成立的。
- **持久化**：客户端 `Config.Language` 默认 `"English"`（`Client/Envir/Config.cs`），属于 `[ConfigSection("Graphics")]`，存 `.\Zircon.ini`（exe 同目录，启动读、退出写）。
- **下拉框数据源**：`Globals.Languages = { "English", "Chinese" }`（`LibraryCore/Globals.cs:143`）——这是"语言注册表"，加语言必须改这里；`DXConfigWindow.cs:533` 遍历它填充下拉框。
- **外部覆盖能力**：语言类仍带 `[ConfigPath(@".\Translations\ChineseMessages.ini")]` —— 玩家可在 exe 旁放 ini 覆盖代码内置文案（2024 年加了 `Disabled` 开关可禁用）。

## 3. 想用中文，怎么做

**WinForms 老客户端**：设置窗口 → 图形页 → Language 下拉选 Chinese；或直接改 `Zircon.ini`：

```ini
[Graphics]
Language=Chinese
```

**Godot 新客户端**：目前完全没有翻译层（grep 整个 GodotClient 无任何本地化代码，UI 是骨架英文）。两条路：

1. 把三个翻译类移植进 GodotClient（纯 C# 字符串类，`LibraryCore` 已有 ConfigReader 可复用）——最贴近原架构；
2. 或改用 Godot 原生 `TranslationServer` + `.po`/CSV。

捷径：只要 Godot 端登录时发 `SelectLanguage { Language = "Chinese" }`（packet 已存在于 LibraryCore），**服务端返回的系统消息就会是中文**——不管客户端 UI 本身有没有翻译。

**字体注意**：老客户端默认字体 `"MS Sans Serif"` 没有中文字形，中文靠 GDI+ 系统字体回退；Godot 端需要带 CJK 字形的字体资源。

## 4. 想用日文

完全不存在，需要动 4 处代码：

1. 新建 `JapaneseMessages.cs`（客户端 757 条 + 服务端 313 条日文翻译）；
2. `Globals.Languages` 加 `"Japanese"`（否则下拉框没有选项）；
3. 客户端 `CEnvir.LoadLanguage` + 服务端 `SConnection.Process(C.SelectLanguage)` 的 switch 各加一个 `case "JAPANESE"`；
4. 字体：老客户端改 `Config.FontName` 或接受系统回退；Godot 端准备带日文字形的字体。

⚠️ 坑：两端 switch 无 default，若只改 `Zircon.ini` 写 `Language=Japanese` 而不改代码，服务端静默回落英文、客户端直接崩。

### 5.1 故事要点

1. **接口是原作者 2019 年预留的，且一开始就是为中文留的**：初始提交里中英两个实现类 + 外部 ini 的架构就齐了。Suprcode（LOMCN Mir3 模拟器作者）从一开始就把中文定为第二语言——不是随便挑的，是 Mir2/Mir3 私服圈子**中国架设者占绝对多数**，中文是唯一值得做的第二语言。日文/德文连空壳都没有。

2. **翻译完成是中国开发者社区干的**：2024 年那位 +0800 时区的作者（PR #157）是主要推手；2023 年的中国开发者（YuanBaian 的 QQ 邮箱、Lanaya）也在零星贡献。作者后来接手维护，把中文保持在 100% 覆盖。

3. **为什么现在英文是默认**：`Config.Language` 默认 `"English"`。这符合国际化惯例（英文是项目语言），也保证不了解中文的架设者拿到的是自己认识的语言。

## 6. 全中文化（连数据库一起）的路线

如果连物品名、NPC 对话都要中文，只能改 `System.db`：把 `ItemInfo.ItemName`、`MonsterInfo.MonsterName`、`NPCPage.Say` 等批量替换成中文。代价与风险：

- 数据库是**自定义二进制格式**（非 SQLite），需用 `Tools/SystemDbProbe` 的 MirDB Session 读写（已有工具能读）；
- 对话里的链接 `[Browse Potions:1]` 是服务端按格式解析的，翻译时不能动结构；
- 世界数据是**全服共享**的——改完所有人都看中文，英文版就没了（除非给每个表加语言列，工程量大很多）。

**建议路线**：先用内置中文（UI + 系统消息），数据库英文内容作为"原汁原味"保留；等 Godot 渲染层成型后，在客户端做一层"显示名映射表"（英文名 → 中文名，客户端本地替换）作为可选增强——不动数据库，风险最低，且与多语言接口天然兼容：名字映射放显示层，`Language` 开关控制是否启用。
