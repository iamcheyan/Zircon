## 1. 我们在做什么

把传奇 3（Mir3）Zircon 项目**用 Godot 重构为单机版**（先单机，后 web）。

仓库里原来有两套东西：

- **服务端**（ServerLibrary / ServerCore / LibraryCore）—— 游戏规则
- **客户端**（Client）—— 提线木偶，只管显示

## 2. 核心认知：游戏规则住在服务端

**打怪掉什么、伤害怎么算、怪物会不会追你、升级要多少经验 —— 这些规则全在服务端，客户端一行都没有。**

原版客户端是个"提线木偶"：

```
服务端算出"怪死了掉屠龙刀" ──网络──► 客户端只是照着显示：画个怪、画把刀
```

客户端连"怪有多少血"都不知道，全是服务端告诉它的。

**做单机，裁判（服务端）没了，谁来执行规则？**

| 方案 | 结果 |
|---|---|
| A. 把服务端代码原样搬进来 | ✅ 我们的方案。规则一行不改 |
| B. 在 Godot 里从头重写规则 | ❌ 几万行（309 种怪 AI、1078 件装备、174 个魔法、伤害公式…）手抄一遍，抄错一个公式游戏就坏 |

类比：Minecraft 单人玩时，你电脑里其实跑着一个"内置服务器"。**单机 ≠ 没有服务端，单机 = 服务端搬进本地。**

## 3. 复用边界（哪些沿用，哪些重写）

| 层 | 处置 | 说明 |
|---|---|---|
| ServerLibrary + LibraryCore | ✅ **复用** | 怪物 AI / 魔法 / 物品 / 任务 / 主循环，纯 C#、跨平台 |
| System.db | ✅ **复用** | 244 地图 / 309 怪 / 1078 物品… 全在里边，明文可读 |
| Data/*.Zl 图库、Map/*.map、Sound/*.wav | ✅ **复用** | 已下载在 Debug/ |
| 渲染层 | ♻️ **重写** | 旧客户端 WinForms + D3D11 钉死在 Windows，Godot 里全重写 |
| UI / 输入 | ♻️ **重写** | Godot Control 系统 |
| LocalBridge 桥接层 | 🔨 **自己发明** | 见下节，这是改造的技术核心 |
| 旧客户端 Client/ | 🚫 不碰 | 当参考书，代码不用 |
| Server/（DevExpress 编辑器） | 🚫 不碰 | Windows only，单机不需要 |

**工作量比例：复用约 7 成（规则），自己写约 3 成（渲染 + 桥）。** 这就是当初定方案时坚决不"在 Godot 里重写逻辑"的原因。

## 4. 单机化的原理：把服务器搬进肚子里

**不是"单机版去连一个迷你服务器"，而是把服务端代码直接嵌进游戏进程。**

| 路 | 做法 | 问题 |
|---|---|---|
| A. 本地连本地 | 服务端开端口，客户端 TCP 连上去 | 多一层网络，多余 |
| B. 进程内直连（我们的方案） | 不建网络，服务端代码变普通函数调用 | 零网络，快 |

原架构靠 TCP 传数据包（packet）：

```
服务端 SConnection.Send(S.*) → 序列化 → TCP → 客户端 CConnection.Process(S.*)
客户端 CEnvir.Enqueue(C.*)   → TCP → 服务端 SConnection.Process(C.*)
```

单机化就是**把这条链路短路成进程内调用**：

```
┌────────────────────┐      直接调 PlayerObject 方法      ┌──────────────────┐
│  Godot 输入 / 渲染  │ ────────────────────────────────► │  ServerLibrary    │
│      C# 脚本       │                                    │    原样逻辑       │
└─────────┬──────────┘                                    └─────────┬────────┘
          │                                                     │ 产生 S.* packets
          │            ┌───────────────┐                        │
          └────────────│  LocalBridge   │ ◄──────────────────────┘
                       │  拦包不发包     │
                       │  → Godot 信号  │ ────► Godot 场景更新（位移/特效/背包…）
                       └───────────────┘
```

关键发现（读代码确认）：

- **发包出口很干净**：`BaseConnection.Enqueue(Packet)` 是 `virtual`，服务端几千处 `player.Enqueue(new S.XXX{...})` 一行不用改，只要在桥接层拦截。
- **⚠️ 已知坑**：`SConnection` 是 `sealed`（ServerLibrary/Envir/SConnection.cs:19），不能直接继承。方案：去掉 `sealed`（一行改动）或在 `BaseConnection.Enqueue` 层拦截。
- **网络层只有两个函数**：`StartNetwork()`（开端口）和 `WebServer.StartWebServer()`。单机版跳过这两行，其余逻辑原样跑。

比喻：原来用邮局寄信（网络），现在改成当面递交（函数调用）。**信的内容、写信的人全都不变，只有投递方式变了。**

## 5. 主循环 EnvirLoop（服务端怎么"活"起来）

位置：`ServerLibrary/Envir/SEnvir.cs:1373`。结构：

```
while (Started)                    ← 无限转，直到主动停止
{
    1. Now = 当前时间
    2. 处理新连接（网络用，单机跳过）
    3. 每个玩家 StartProcess()     ← 玩家逻辑
    4. 处理一批 ActiveObjects      ← 关键：怪物 AI 在这里 tick
         ├─ 每次循环只处理一小撮（时间切片，1ms 预算）
         ├─ 每个怪：ProcessAI / ProcessSearch / ProcessRoam
         │         / ProcessTarget / ProcessRegen
         └─ 即：巡逻 → 发现目标 → 追击 → 攻击 → 回血
    5. 定时：存档 / 事件计时 / 沙巴克计时
}
```

启动时还会：加载数据库（已实测 ~2 秒）→ 按刷新表（1471 个刷新点）把怪生成到地图 → 启动存档线程。

**跑起来的形态**：一个控制台进程，无窗口无画面。后台在无声地运转——每帧几十上百个怪各自巡逻、互殴、回血、死亡、重生。**看不见，但活着。**

## 9. 术语表（新手向）

| 术语 | 含义 |
|---|---|
| packet（包） | 服务端和客户端之间传递的一段数据，如"怪移动了""你掉血了"。单机化就是让它在进程内直接传递 |
| tick | 游戏循环的一帧。服务端循环每 tick 推进一次世界 |
| ServerPacket / ClientPacket | S.* = 服务端发给客户端的包；C.* = 客户端发给服务端的包 |
| LocalBridge | 我们的桥接层：把"发包走网络"改成"直接递到 Godot 手里" |
| EnvirLoop | 服务端主循环，整个游戏世界的发动机 |
| ActiveObjects | 当前活跃的世界对象列表（怪、掉落物、特效…），循环逐批处理 |
| MirDB | 自研二进制数据库格式，System.db 就是用它读的 |
| System.db | 全部游戏定义（地图/怪物/物品/魔法/任务），不加密，直接读 |
