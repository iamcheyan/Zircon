# 33：GM 管理命令手册

GM（游戏管理员）命令在游戏内聊天框输入，前缀为 `@`。本文覆盖权限判定机制、三种 GM 模式、全部 Admin 命令的参数，以及已知上游问题。

## 权限判定机制

判定链（`ServerLibrary/Envir/Commands/AdminCommandHandler.cs`）：

```
IsAllowedByPlayer(player) = Account.Admin || Account.TempAdmin
```

- `AccountInfo.Admin`：持久化字段，存在 `Users.db`。`Admin=True` 的账号**每次登录都自动具备 GM 权限**，重启不丢。
- `AccountInfo.TempAdmin`：运行时字段，登录时设置，断开即清。仅通过 MasterPassword 逃生通道获得（见下）。
- `AccountInfo.IsAdmin(includeTemp)`：`Admin` 与 `TempAdmin` 的组合查询，用于登录后其他功能判定。

非管理员发送 `@` 命令会被**静默忽略**（`AbstractCommandHandler.Handle` 只在 `IsAllowedByPlayer` 为真时执行），无任何回执——这是排查命令不生效时的第一信号。

### 逃生通道（MasterPassword）

上游设计：账号栏输入**角色名**（非邮箱格式）+ 密码 = `Config.MasterPassword`（`ServerLibrary/Envir/Config.cs:27`，当前值 `REDACTED`），登录后该账号 `TempAdmin = true`，同样获得全部 GM 权限。临时性：重启或重新登录即失效；适合忘记权限、库被改坏时应急，不影响持久化 `Admin`。

> 注意：`SEnvir.Login`（`ServerLibrary/Envir/SEnvir.cs:3266`）中该判定是"非邮箱格式且密码匹配"，角色名不能是邮箱格式。

## 三种 GM 模式

`PlayerObject.GameMaster / Observer / Superman` 为运行时标志。管理员登录时在 `PlayerObject.cs:229` 按配置自动开启：

```csharp
if (Character.Account.Admin || Character.Account.TempAdmin)
{
    GameMaster = Config.AdminStartInGamemasterMode;   // Server.ini 当前 True
    Observer  = Config.AdminStartInObserverMode;      // Server.ini 当前 True
    Superman  = Config.AdminStartInSupermanMode;      // Server.ini 当前 True
}
```

| 模式 | 开关命令 | 效果 |
|---|---|---|
| GameMaster | `@GAMEMASTER` | 怪物/PK 不主动攻击你 |
| Observer | `@OBSERVER` | 穿墙、隐身（不可被看到/选中） |
| Superman | `@SUPERMAN` | 无敌：不受伤、不耗蓝 |

三个开关命令均无参数，来回切换，成功时收到 System 回执 `GAMEMASTER activated/deactivated`（以此类推）。

> 因为登录自动开启，管理员进游戏首条 `@SUPERMAN` 的合法回执是 `SUPERMAN deactivated`（把自动开启关掉），再发一条才是 `activated`。

## Admin 命令全集

以下参数个数为**最小必需**（不含命令名），可选参数标注 `[可选]`。所有命令作用于执行者自身或指名玩家，怪物/物品名忽略大小写。

| 命令 | 参数 | 说明 |
|---|---|---|
| `@ADDSTAT` | `槽位 属性 数量` | 给指定装备槽物品加属性。槽位为 `EquipmentSlot` 枚举（如 `Weapon`），属性为 `Stat` 枚举（如 `DC`） |
| `@BAN` | `玩家 [天数]` | 封禁账号。缺省 365 天（1440×365 分钟） |
| `@CHATBAN` | `玩家 [分钟]` | 禁言 |
| `@GLOBALBAN` | `玩家 [分钟]` | 禁全服喊话 |
| `@CLEARIPBLOCKS` | 无 | 清空本账号 IP 封禁记录 |
| `@CREATEGUILD` | `行会名` 或 `玩家 行会名` | 创建行会；执行者无行会时用前一种，指定玩家时用后一种 |
| `@ENDCONQUEST` | `城堡名` | 立即结束该城堡当前的攻城战（`war.EndTime = MinValue`） |
| `@STARTCONQUEST` | `城堡名` | 立即开始攻城战（`SEnvir.StartConquest(castle, true)`） |
| `@TAKECASTLE` | `城堡名` | 夺城：执行者行会占领；无行会则解除当前占领 |
| `@GCOLLECT` | 无 | 强制垃圾回收（`GC.Collect()`） |
| `@GIVEGAMEGOLD` | `玩家 数量` | 给账号加商城币 GameGold |
| `@TAKEGAMEGOLD` | `玩家 数量` | 扣账号商城币 |
| `@GIVEHORSE` | `玩家 类型` | 给坐骑，类型为 `HorseType` 枚举 |
| `@GIVESKILLS` | `玩家` | 按职业给该玩家所有职业技能（Lv.1，跳过 Discipline 系） |
| `@GOTO` | `玩家` | **上游 bug**：传送到该玩家位置，但当前实现是 `Teleport(自己当前地图, 自己当前位置)`（`Goto.cs`），等于原地不动，勿用于实际传送 |
| `@KICK` | `玩家` | 踢下线 |
| `@LEVEL` | `数值` 或 `玩家 数值` | 设等级（后者给指名玩家） |
| `@LEVELSKILL` | `玩家 技能名 等级` | 设技能等级（示例注释 `@levelskill John healing 5`） |
| `@LEVELWEAPON` | 无 | 武器升满级（到 `WeaponExperienceList` 上限） |
| `@MAKE` | `物品名 [数量] [玩家]` | 造物。货币类物品走货币体系，缺省数量 1；可选第三参数指定给谁 |
| `@MOVE` | `地图 [X Y]` | 传送。`地图` 为地图 `FileName`（如 `0`）；带坐标则精确传送并校验边界，不带则随机位置 |
| `@MONSTER` | `怪物名 [数量]` | 当前地图生成怪物，缺省 1 只 |
| `@PROMOTEFAME` | `数值` 或 `玩家 数值` | 加声望 |
| `@REBOOT` | 无 | 服务器重启流程（清理 MarketPlace 等） |
| `@RECALL` | `玩家` | 把玩家拉到你身边 |
| `@REMOVECAPTION` | `玩家` | 清除称号 |
| `@REMOVEPKPOINTS` | `玩家` | 清除 PK 点（移除 `BuffType.PKPoint`） |
| `@RESETDISCIPLINE` | `玩家` | 重置武学（Discipline）加点 |
| `@SETCOMPANIONLEVEL` | `等级` | 同伴等级设为 1–15（作用于自己已召唤的同伴） |
| `@SETCOMPANIONSTAT` | `加点档 属性 值` | 设置同伴指定加点档（3/5/7/9…）的属性；要求同伴当前等级高于该档 |
| `@SETHERMITSTAT` | `属性 数量` | 设置自己的隐士点数分配 |

错误处理：参数不足/解析失败回 `UserCommandException`；找不到玩家/怪物/物品/城堡/地图都有明确报错；被静默吞掉（无任何回执）只发生在**非管理员**。

## 已知问题与注意事项

1. **`@GOTO` 上游 bug**（`ServerLibrary/Envir/Commands/Command/Admin/Goto.cs`）：`player.Teleport(player.CurrentMap, player.CurrentLocation)` 传送到自己当前位置，等于原地传送。期望是传送到**目标玩家**位置。未修复（上游代码，避免与其他人改动冲突），需要时可改用 `@MOVE` + 目标坐标。
2. **`@LEVELWEAPON` 无玩家参数**：只作用于执行者当前武器。
3. **`@REBOOT` 有全局副作用**：会走服务器重启流程，慎用。
4. **命令不区分大小写**：`@superman` 与 `@SUPERMAN` 等价（`input[0].ToUpper()` 后匹配）。
5. **聊天文本上限**：`C.Chat.Text` 超 `Globals.MaxChatLength` 会被服务器直接丢弃（`SConnection.cs:597`）。
