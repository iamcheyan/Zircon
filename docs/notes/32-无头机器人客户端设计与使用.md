# 32：无头机器人客户端

机器人不是服务器里的特殊 NPC，而是 20 个普通账号通过 `BotRunner` 登录。服务器只会看到普通 `SConnection`、`PlayerObject` 和普通 `C.*` 请求，因此等级、装备、经验、背包、金币和位置都由服务器的 `Users.db` 持久化。

## 组件

- `BotRunner/`：无渲染客户端。一个进程管理最多 20 个独立 TCP 连接。
- `Tools/BotProvisioner/`：一次性创建机器人账号、角色、装备、技能和初始状态；重复执行不会覆盖已经存在的机器人。
- `LibraryCore/`：复用原有 packet 定义和 `BaseConnection`。

## 初始化

必须先停止服务器，确保数据库不会同时被两个进程写入：

```bash
dotnet run --project Tools/BotProvisioner -- \
  /path/to/server/Database \
  --reference TestHero --count 20
```

默认创建 `bot01@bot.local` 到 `bot20@bot.local`，密码为 `bot123456`。每个账号一个角色，职业按战士、法师、道士、刺客轮换，性别交替，等级、外观、装备、技能和消耗品有差异，并在装备栏的火炬位置装备 `Bright Candle`。初始地图、实例、绑定点和坐标从参考角色复制，并在附近错开坐标。

先检查数据库而不写入（数据库目录必须是第一个参数）：

```bash
dotnet run --project Tools/BotProvisioner -- /path/to/server/Database --dry-run
```

查看采集、钓鱼、宠物、副本、礼包和市场配置：

```bash
dotnet run --project Tools/BotProvisioner -- /path/to/server/Database --dry-run --resource-report
```

如果机器人之前已经运行到地图较远位置，可以在停服后只重置位置并保留其余数据：

```bash
dotnet run --project Tools/BotProvisioner -- /path/to/server/Database \
  --reference TestHero --count 20 --reset-positions
```

## 运行

启动服务器后：

```bash
dotnet run --project BotRunner -- BotRunner/BotRunner.json
```

Ctrl+C 会让所有连接退出。机器人当前行为包括服务器握手、登录、进入游戏、观察世界、以出生点为中心巡逻、追踪附近怪物、近战攻击、法师/道士按真实攻击技能施法、追踪并拾取地面物品、低生命值使用服务器标记的自动药品、聊天以及死亡后的回城复活。伙伴对象虽然由服务器以怪物对象广播，但机器人不会把玩家伙伴误当作 PvE 目标。

职业行为由无头客户端状态机驱动：战士和刺客会按已学习技能选择真实攻击技，法师会周期性维护 `MagicShield` 并在战斗中保持施法和走位，道士会维护护盾、治疗队友，并在没有自己召唤物时使用服务器真实的骷髅/神兽/恶魔召唤技能。每次职业技能之后都会重新走位，战斗每几次攻击也会重新定位；日志中的 `active` 行会报告每个机器人的移动、攻击、施法、寻怪和召唤计数，用于确认不是站桩。

社交和生活行为还包括：Bot01 邀请 Bot02-Bot08 组队，其他机器人接受邀请并跟随队长；Bot03、Bot07、Bot11、Bot15、Bot19 使用数据库中持久化的伙伴，由服务器负责伙伴的生成、跟随和战斗；机器人会加入服务器已有的 `Starter Guild`，由服务器持久化公会成员关系；Bot01/Bot02 会在相邻并互相面向时走完真实的交易请求、接受、打开、金币确认和关闭流程；Bot04、Bot08、Bot12、Bot16、Bot20 会使用数据库中持久化的不同坐骑，在允许骑乘的地图按周期上下马；道士会读取队伍成员的生命状态，在队友或自己低生命时使用治疗类技能；检测到装备耐久较低时寻找修理 NPC，主动走到 NPC 附近再发送修理请求；检测到带任务的 NPC 时主动接近并发送任务接受/完成请求；药品不足时通过 NPC 的 BuySell 页面购买服务器允许的自动药品；击杀怪物后会尝试使用 Harvest 请求采集归属掉落；背包达到一定数量后会请求服务器整理背包。机器人移动前会读取客户端地图碰撞数据，优先选择目标方向，遇到静态阻挡会自动偏转，减少原地撞墙。Bot05、Bot10、Bot15、Bot20 是资源行为样本：会把当前武器暂存到背包、装备真实镐子，并尝试通过 `AutoPathWaypoint` 前往可采矿地图；服务器没有可达路线时会退回普通战斗行为，不会持续刷寻路请求。配置存在时，Bot02/07/12/17 会按等级尝试加入副本，Bot01/06/11/16 会使用鱼竿和钓鱼服在真实钓鱼区域抛竿并自动收竿，机器人会自动打开背包礼包并确认奖励。网络断开时单个机器人会独立退避重连，重新进入游戏时清除旧对象缓存。上述行为全部复用服务器现有的组队、交易、公会、坐骑、伙伴、NPC、任务、装备、物品、治疗、采集、礼包、钓鱼、副本和寻路协议。

## 多人战斗与经济行为

- `EnableBotPvP=true` 时，Bot01-Bot08 和 Bot09-Bot16 组成两支队伍；同队不互相选为 PvP 目标，队伍外按周期进行集结、单挑和小规模战斗。Bot05/06、Bot10/11、Bot15/16、Bot20/01 还配置了专门的决斗配对。
- 机器人把攻击模式切换为服务器已有的 `AttackMode.All`，但目标、攻击距离、技能冷却、安全区、正当防卫和死亡结果仍由 `PlayerObject` 校验。法师会维护魔法盾，道士会治疗、召唤骷髅/神兽/恶魔并消耗护身符，所有职业都会使用已学习的真实技能。
- 机器人死亡后由服务器生成正常掉落；机器人只发送普通 `C.PickUp`，服务器继续按掉落可见性、组队/公会保护时间、背包容量和物品归属判断是否允许拾取。测试环境打开 `Config.DropVisibleOtherPlayers`，但没有取消保护时间或物品校验。
- 每个机器人持有持久化金币。低生命或低魔法时使用 `CanAutoPot` 药品；补给周期会寻找有药品、卷轴或护身符商品的 NPC，进入 BuySell 页面后按职业选择商品并发送普通 `C.NPCBuy`。捡到的普通装备、矿石和杂物会在出售周期前往允许对应物品类型的 NPC，发送普通 `C.NPCSell`，保留装备栏、锁定物品和精良装备。
- 服务器的 NPC 交互范围统一为 `Config.NPCInteractionRange=2`。`NPCCall`、NPC 按钮、购买和出售都必须保持在该范围内；玩家离开范围时服务端清空 NPC 会话，防止无头客户端通过远距离请求刷物品或金币。

## 注意

- 同一个账号只能有一个在线连接，因此 20 个机器人必须使用 20 个账号。
- 修改 `Users.db` 前必须停止服务器并保留 MirDB 自动备份。
- 当前机器人客户端不渲染地图，不直接修改角色数据；所有运行时变化必须通过服务器规则产生。
- 当前测试数据库没有配置钓鱼区域、副本、礼包、宝箱或市场记录；相关行为会自动跳过，配置真实内容后才会发送对应协议。
- 资源工具的参数顺序是：数据库目录、再跟选项；例如 `... -- Debug/Server/Database --dry-run --resource-report`。
- `VerboseNetworkLogging` 默认关闭，避免底层发送队列日志淹没行为日志；调试网络包时才打开。
- 如果服务器启用 `CheckVersion`，需要为 `BotConnection` 配置与服务器匹配的客户端 hash；测试配置目前关闭了版本检查。
