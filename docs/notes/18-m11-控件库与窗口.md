# 18 · M11 控件库 + 窗口（WindowManager / 状态窗口 / UI CanvasLayer）

> 里程碑 M11：把旧客户端的窗口控件体系移植到 Godot，并接入一个真实窗口验证整条链路。
> 对应原版 `Client/Controls/`（~26 个控件类）与窗口管理逻辑（`DXWindow.Windows` + 激活窗口）。

## 之前的问题（M11 调研结论）

- `GodotClient/Controls/` 已有 6 个基础控件（DXWindow / DXControl / DXButton / DXLabel / DXImageControl / MirSkin），但**没有窗口管理器**：窗口的 Z 序、Esc 关闭、开关切换都无处安放。
- 控件库只在独立测试场景（UITestScene）里自检过，**从未接入主流程**。
- **`.Zl` 图库读取器不支持 ZL2 压缩容器**：`Interface.Zl`（所有 UI 窗口的背景/按钮贴图源）正是 ZL2 格式，一读就是 0 帧——这是整个控件库落地的前置阻塞，本里程碑一并解决。

## 这次做了什么

### 1. ZL2 压缩容器支持（ZlReader.cs）——前置依赖

原版 `.Zl` 分两种格式：旧格式（version 0/1，帧数据按 Position 直接 seek）和 **ZL2 容器**（version 2，帧数据按"索引条目"存放、Deflate 压缩）。`Interface.Zl`、`GameInter.Zl` 等 7 个 UI/界面图库都是 ZL2。

按原版 `RenderingCore/Library/MirLibrary.cs` 的 `TryReadCompressedContainer` 移植：

- **头部**（43 字节）：`ZL2` 签名 + version + 图像数 + atlas 数 + 默认压缩 + flags + 保留 + metadata 偏移/大小 + index 偏移/大小；
- **index 块**：`Zl2Entry` 列表（Type / Id / 解压后大小 / 压缩后大小 / 文件偏移 / 压缩方式 / codec），帧的 `Position` 字段在此格式下就是 **entry Id**（0 也是合法 id）；
- **metadata 块**：version + 帧数 + 帧定义（与旧格式同构，`ZlImage.Read` 复用）；
- **取帧**：seek entry 偏移 → 读压缩段 → `DeflateStream` 解压 → 取 **primary 段**（偏移 0、`StoredImageDataSize` 字节）按帧 codec 解码；primary 尺寸不符时回退 Bc7 段。

实测解剖 `Interface.Zl`：282 帧全是 **Png codec**（primary 段就是 PNG 数据，如 164 帧 420×448 的 primary 段 11243 字节以 `89504e47` PNG 签名开头），解压 → PNG 解码路径完整跑通。解码链复用现有 `BcnDecoder`（Dxt1/Dxt5/Bc7）与 PNG 加载。

顺带修掉 MirSkin 的路径 bug：先 `StartsWith("Data/")` 再 `Replace('\\','/')` 顺序反了，导致 `Data\Interface.Zl` 拼出 `Data/Data/Interface.Zl`，所有 Windows 反斜杠路径的图库都加载失败。

### 2. WindowManager（GodotClient/Controls/WindowManager.cs）

原版没有独立 WindowManager——窗口管理内嵌在 `DXWindow.Windows` 静态列表 + ActiveScene 里。Godot 版集中成静态类：

- `OpenWindows` 列表（尾部 = 最上层窗口）；`Open` 首次调用时把窗口挂到传入的 CanvasLayer 父节点；`Close` / `Toggle` / `CloseTop`（供 Esc）/ `BringToFront`；
- `BaseZ = 100`，`RefreshZOrder` 按打开顺序给可见窗口设 `ZIndex = BaseZ + i`，顺带清理隐藏残留；
- `DXWindow._GuiInput`：点击窗口任意处即 `BringToFront`（原来只在标题栏拖拽时置顶），仍只允许在标题栏区域拖动。

### 3. UI CanvasLayer + StatusWindow 真实接入（GameScene.cs / StatusWindow.cs）

- `GameScene._Ready` 建 `_uiLayer = new CanvasLayer { Layer = 10 }`，UI 层独立于世界层（Layer 0），Z 序由 WindowManager 从 100 起分配；
- 新增 `StatusWindow : DXWindow`：位置 (40,80)、尺寸 280×230、标题"角色状态"、背景贴图 `Interface.164`（即前文验证的 420×448 帧）、8 行 DXLabel（角色/职业/生命/魔法/位置/方向/地图/周围物体，y 从 36 起每行 23px，FontSize 13，米黄色）；
- `Refresh(...)` 节流（200ms，`_Process` 里仅窗口可见时调用）且**文本未变不重绘**（逐行对比），避免每帧刷文本；
- 数据绑定玩家真实状态：`OnStatsUpdate` 存 `MaxMana`（PlayerRenderer 新增 `public int MaxMana`），位置/方向/地图名/周围物体数取自 StartInfo 与场景对象表；
- 按键：**F2** 切换状态窗口（`WindowManager.Toggle`），**Esc** 关闭最上层窗口（`WindowManager.CloseTop`），并入已有 `_Input`（方向键移动 + F12 截图）。

## 关键决策

1. **ZL2 只取 primary 段 + 元数据 codec 解码**：原版有 runtime preference / Bc7 / fallback 多段选择，Godot 端目标是 BGRA32 单纹理，primary 段（PNG/BCn）直接解码即可覆盖全部实际文件；解码尺寸不符时才回退 Bc7 段。
2. **atlas 页不读**：原版 atlas 受 `GetUseZlAtlasPages()`（默认 false）门控，Godot 端不需要；metadata 块内 atlas 定义与 layer mappings 是块内自包含的，跳过不影响后续读取。
3. **WindowManager 用 ZIndex 管理 Z 序**：而非仅依赖 Godot `MoveChild` 置顶；两者结合（置顶 + 数值化 Z 序）保证任意打开/关闭顺序下层级正确。
4. **状态窗口做 M11 接入演示**：它同时是 M12 MainPanel HUD 的前置验证——CanvasLayer UI 层、F2/Esc 按键通道、窗口开关/置顶/节流刷新全链路已跑通，M12 照此模式扩展。
