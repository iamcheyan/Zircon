## 1. 目标与链路

```
键盘方向键
  → C.Move { Direction, Distance=1 }        (客户端发包)
  → 服务端 Player.Move 裁决                  (撞墙/超时则拒绝)
  → S.ObjectMove 广播                        (服务端回包, 含自己)
  → 客户端更新位置 + Walking 动画 + 插值     (6帧×100ms 平滑移动)
  → 地图 CenterOn 跟随, 玩家始终居中
```

## 2. 两个重要发现

### 发现一：服务端移动成功回的是 `S.ObjectMove`，不是 `S.UserLocation`

查服务端源码 `PlayerObject.Move()`：

- **成功** → `Broadcast(new S.ObjectMove { Location = CurrentLocation, ... })`——广播给所有玩家（含自己）
- **失败**（撞墙/冷却中/距离不合法）→ 回 `S.UserLocation`（原地不动，通知客户端"没走成"）

我们的客户端只处理了 `UserLocation`，没处理 `ObjectMove`，所以**服务端其实一直在正确响应，只是客户端把回包当未处理包丢了**。日志里的证据：`[Net] 入队: ObjectMove` + `[Net] 未处理包: ObjectMove` 反复出现。

修复：新增 `ObjectMoveEvent`，`GameScene` 订阅后判断 `ObjectID == 玩家ObjectID` 才处理（其他玩家的移动留给 M4），与 UserLocation 走同一条插值逻辑。

### 发现二：ObjectID 的一致性有惊无险

一开始担心 `StartInformation.ObjectID`（玩家在数据库的标识）与 `ObjectMove.ObjectID`（服务端运行时对象 ID）不是同一个数。查原客户端 `UserObject` 构造：`ObjectID = info.ObjectID`，与 `Process(S.ObjectMove)` 的比对 `MapObject.User.ObjectID == p.ObjectID` 完全同源——服务端广播的就是玩家对象自己的 ObjectID。可以放心比对。

## 3. 顺带修掉的动画相位 bug

`SetAnimation` 里 `FrameStartMs = 0`（而不是"当前时间"）：动画计时基准是 0，而引擎时间戳是几十亿毫秒，导致**动画从随机帧开始**、相位漂移。改成 `Godot.Time.GetTicksMsec()` 后，动画稳定从第 0 帧播放。
