# 讨论记录 11：M2 玩家真实外观渲染——从"红方块"到"真角色"

> 日期：2026-08-06
> 关联：讨论 06 讲清了 .Zl 图库与 .map 地图的读取；本篇是把"玩家"从占位红方块升级成**真实游戏角色**（头发、身体、装备分层绘制），并完成窗口模式下的完整视觉验证。
> 结论：M2 完成。玩家按服务端下发的外观数据（性别/发型/发色/装备）从图库里取出对应贴图分层绘制，站立动画正常，地图与玩家同屏可见（地图区域 96% 有内容）。渲染位置/帧号公式全部移植自原客户端，与服务器逻辑零改动。

---

## 1. 目标：玩家不再是一个方块

之前的"玩家"是一个 32×48 的红色占位方块。M2 要做的：**登录进游戏后，屏幕中央站着一个真正的传奇角色**——有头发、有脸、有身体，将来还有装备。

难点在于：传奇的渲染不是"一张角色图"，而是**好几层贴图叠在一起**，像拼图：

```
背武器 → 身体（盔甲/衣服）→ 头（头盔或头发）→ 前武器/盾牌
```

每层都来自不同的图库文件，帧号还要按"动画类型 × 方向 × 帧"计算。

## 2. 数据从哪来

服务端的 `StartGame` 回包里自带一份 `StartInformation`（外观信息），包含渲染需要的全部字段：

- 性别（决定用男版还是女版图库）
- 发型、发色
- 盔甲形状与颜色（决定身体贴图）
- 时装、头盔、盾牌、武器形状

TestHero 是无装备的新手战士：`ArmourShape=0` → 身体用 M-Hum 图库；`HairType=1` → 头发用 M-Hair 图库；无武器 → 但武器层仍要画（空帧）。

## 3. 三个核心公式（从原客户端移植）

**帧号**：动画播放不是一帧一帧贴图排好，而是"基准 + 方向 × 间隔"：

```
DrawFrame = 帧索引 + 动画起始帧 + 方向偏移 × 方向号
```

**层偏移**：身体/头发/武器各占一个"5000 帧"的大区段，同帧号加不同区段就是不同层：

```
身体帧   = DrawFrame + (时装编号 或 盔甲编号 % 11) × 5000
头发帧   = DrawFrame + (发型 - 1) × 5000
武器帧   = DrawFrame + (武器形状 % 10) × 5000
```

方向：8 个方向用 0~7 编号（向下是 4），图库里每个方向占 10 帧一组，所以方向偏移 = 方向号 × 10。

**帧表**：站立动画 = 4 帧循环（Start=0, OffSet=10），每帧 500ms；行走动画 = 6 帧（Start=80）。这些数字定义在 `FrameSet.Players` 帧表里，原客户端用同一张表。

## 4. 实现：PlayerRenderer 与 LibraryCache

- **`LibraryCache`**（共享图库缓存）：所有渲染组件共用一个 .Zl 图库加载器，同一图库只解压一次。地图、玩家都用它，避免重复加载 5 万张图。
- **`PlayerRenderer`**（Node2D 渲染节点）：按上面的公式每帧从图库取贴图，`DrawTextureRectRegion` 分层画到屏幕上；`_Process` 里按时间推进动画帧，每 500ms 换一帧。

## 5. 玩家位置的坑：一个让玩家"永久消失"的 bug

进游戏后玩家应该站在屏幕中央。实测却完全看不到人。查日志发现：玩家的屏幕坐标算出 `(8090, 8394)`——**几万像素之外**，当然看不见。

根因：第一帧算位置时，地图视野中心还是 0，公式把它放大到几千像素外；而"玩家静止"分支的代码**只更新格子坐标、没有再调用一次"换算屏幕坐标"的函数**，于是位置永远是那个错误的初始值。

修复：每帧都重新换算一次屏幕位置。之后坐标收敛到 `(746, 938)`——正好是屏幕中央（1492×1876 的一半），玩家站定。

## 6. 最终验证（窗口模式，这次是真的）

- 程序内自动截图（见讨论 10 的方法论）→ 视觉模型确认：**荒地地形 + 草丛 + 栅栏木桶等物件正常渲染，玩家小人站在地图中央**，左上角状态栏显示"位置:(153,233) 方向: Down"。
- 像素统计：地图区域 264923/276480 ≈ **96% 有内容**（之前"只有一条竖带"是旧截图误判）。
- headless 回归：0 异常、0 断连。

## 7. 遗留说明

地图背景主要来自 `Tilesc` 图库（已成功加载，12000+ 张图）。另发现 7 个 `.Zl` 文件是 ZL2 压缩格式（更新版容器），涉及部分地表图集，当前读取器暂不支持——**影响的是少数地表纹理，不影响玩家渲染，也不影响地图主体**。后续里程碑（如 M4 周围物体）若需要可补 ZL2 解压。
