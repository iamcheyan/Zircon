# 讨论记录 02：架构方向修正 —— 从单机改为在线客户端

> 日期：2026-08-06
> 关联：讨论 01 曾定方案为"单机化（LocalBridge）"，本篇记录方向修正。
> 结论：**方案 A 已确认**（服务端原样跑，Godot 客户端直连）。

---

## 1. 为什么要重新考虑方向

讨论 01 的方案是"单机化"——把服务端逻辑嵌进游戏进程，短路 TCP 为进程内调用（LocalBridge）。当时这样选，是因为担心"纯做客户端跟服务端通讯比较麻烦"。

但重新评估后发现这个顾虑**不成立**，而且单机化反而更麻烦。于是修正方向。

## 2. 仓库里其实有两个"服务端"

这是最容易混淆的点，先讲清楚：

| | **Server/** | **ServerCore/**（我们要用的） |
|---|---|---|
| 是什么 | Windows 可视化编辑器（DevExpress 界面） | 无头服务端（纯命令行，真正的游戏服务器） |
| 界面 | 有 GUI，能开窗口编辑数据库 | 没界面，黑窗口/终端 |
| 平台 | 钉死 Windows | 纯 .NET，**Linux 可跑** |
| 用途 | 策划改数值的工具（私服圈用） | 监听端口、跑游戏世界 |
| 我们用吗 | ❌ 不碰 | ✅ 就用它 |

> 你之前看到的"Windows 程序、要单独编译"——那是 `Server/`（编辑器）。真正的服务器 `ServerCore/` 是跨平台的。

## 3. 验证推翻了"连服务端很麻烦"的顾虑

| 验证点 | 结果 |
|---|---|
| 网络协议层（packet 序列化 + TCP 收发） | 全在 `LibraryCore/BaseConnection`，纯 .NET 跨平台，**现成可复用** |
| 原客户端 `CConnection.cs`（5109 行） | 只有"把包应用到画面"耦合 WinForms；**网络收发层干净**，可继承复用 |
| 服务端怎么启动 | `ServerCore/Program.cs` 是现成的无头控制台启动器，编译即跑，**零改动** |

通俗讲：
- 服务端本来就是为"开端口收连接"设计的，让它干本职工作，一行都不用改
- 客户端要新写的网络层就几十行（继承现成的 BaseConnection 写个接收循环）
- 真正的大头（Godot 渲染 + 把包应用到场景）单机方案也 100% 要写，两边一样

## 4. 反直觉的发现：单机化反而要动服务端

| 环节 | 单机化（要动服务端） | 在线客户端（服务端零改动） |
|---|---|---|
| `SConnection` 是 `sealed` | ❌ 要去掉 sealed 或改造 | ✅ 不用碰 |
| 网络层 | ❌ 跳过 StartNetwork、伪造玩家连接 | ✅ 原样跑 |
| 线程 | ❌ EnvirLoop 线程与 Godot 主线程要同步 | ✅ 天然分离 |
| 登录/选角色流程 | ❌ 要自己伪造 | ✅ 原协议现成 |

## 5. 关键洞察：不需要"另一台机器"

服务端是无头控制台进程（没窗口没画面）。所以：

- **本机跑服务端 + 客户端连 `127.0.0.1`** = 开发体验跟单机一样（都在一台机器），但架构直接是最终形态
- 以后上线：服务端搬到别的机器/云服务器，客户端改个 IP 即可

## 6. 两个方案共享 90% 代码，可互转

无论单机还是在线，**Godot 渲染层 + 把包应用到场景的处理层完全一样**（这是大头）。差别只在"包怎么来"：

```
在线客户端:  TCP 收包 → 反序列化 → 处理包 → 渲染    （服务端零改动）
单机:       LocalBridge 进程内递包 → 处理包 → 渲染  （要改服务端）
```

所以不存在"走错路"：就算以后想纯单机（不跑服务器），也只是把网络层换成 LocalBridge，前面写的全都能用。

## 7. 决策

**✅ 方案 A（已确认）：服务端原样跑（本机 127.0.0.1 先跑），Godot 客户端直接连它。**

理由：
1. 最符合原始意图（网游状态：服务端 + 客户端）
2. 服务端零改动 = 少踩 3 个坑（sealed、跳网络、线程同步）
3. 架构一步到位，web 化/上线直接沿用
4. 本机开发体验与单机一样方便

## 8. 客户端要写的东西（对比讨论 01 的变化）

- **网络层**：不是 LocalBridge，而是继承 `LibraryCore/BaseConnection` 写接收循环（参考原 CConnection 的收发部分，几十行）
- **登录流程**：原协议现成（Connect → CheckVersion → Login → SelectCharacter → StartGame）
- **渲染 / UI / 输入**：不变，Godot 全重写
- **.Zl / .map 读取器**：不变，移植自 LibraryEditor
- **服务端**：一行不改（实测已在 Linux 跑通，见讨论 03）

## 10. 术语对照

| 术语 | 通俗解释 |
|---|---|
| ServerCore | 真正的游戏服务器，无头进程，Linux 可跑 |
| Server/ | Windows 编辑器（策划工具），我们不碰 |
| BaseConnection | 网络收发的基类，跨平台现成，客户端继承它 |
| CConnection | 原客户端的网络处理类，收发层可参考、渲染层要重写 |
| packet（包） | 服务端和客户端之间传的"指令信"，如"你走到了(x,y)""怪打你掉 50 血" |
| 127.0.0.1 | 本机地址，客户端连它 = 跟本机的服务端通讯 |
