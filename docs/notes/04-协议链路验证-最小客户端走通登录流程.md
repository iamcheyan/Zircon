> 日期：2026-08-06
> 关联：讨论 03 把服务端跑起来了（TCP 通），本篇验证协议链路端到端通（握手→版本→登录业务）。
> 结论：**第 1 步全部完成。** ServerCore 监听 + 客户端复用 BaseConnection + 真实 packet 收发 + 服务端业务逻辑响应，全链路打通。

## 1. 目标

讨论 03 验证了 TCP 连通（能连上端口）。但"TCP 通"不等于"协议通"——还要验证 packet 能正确序列化/反序列化、服务端能处理客户端发的包、客户端能收到服务端回的包。本篇用最小 .NET 客户端走一遍登录协议，证明整条链路可用。

## 2. 协议流程（从源码梳理）

连接建立后的包交互（`SConnection.cs:270` / `CConnection.cs:128`）：

```
客户端                              服务端
  │  TCP connect                      │
  │ ────────────────────────────────► │
  │                                   │
  │ ◄──────────────── Connected ────  │  服务端确认连接
  │ ──── Connected ─────────────────► │  客户端回握
  │                                   │
  │  (CheckVersion=True 时)           │
  │ ◄──────── CheckVersion ─────────  │  服务端要版本校验
  │ ──── Version(ClientHash) ───────► │  客户端发 dll 的 SHA256
  │ ◄──────── GoodVersion ──────────  │  校验通过 → 进 Login 阶段
  │                                   │  (或 Disconnect: WrongVersion)
  │  (CheckVersion=False 时)          │
  │ ◄──────── GoodVersion ──────────  │  跳过校验直接进 Login
  │                                   │
  │ ──── Login(账号,密码) ──────────► │  客户端请求登录
  │ ◄──────── S.Login(Result) ──────  │  服务端回结果(BadPassword/OK/...)
  │                                   │
  │ ◄──────── Ping ─────────────────  │  服务端定期心跳
  │ ──── Ping ──────────────────────► │  客户端回心跳
```

关键发现：
- **`Config.CheckVersion` 可关闭版本校验**（`SConnection.cs:272`）。我们没有 Godot 客户端 dll，hash 肯定不匹配，所以验证阶段先关掉（`Server.ini` 里 `CheckVersion=False`）。
- **packet 路由用反射**（`BaseConnection.cs:313` `ProcessPacket`）：服务端/客户端找 `Process(具体PacketType)` 方法，找不到则抛 `NotImplementedException`。所以处理一个包 = 写一个 `public void Process(XxxPacket p)` 方法。

## 3. 最小验证客户端（Tools/ClientProbe）

继承 `LibraryCore/BaseConnection`，实现关键包的处理：

```csharp
class TestConnection : BaseConnection
{
    public TestConnection(TcpClient client) : base(client) { }
    public void StartReceive() { BeginReceive(); }  // public 包装 protected 方法

    public void Process(G.Connected p)   { Enqueue(new G.Connected()); }  // 回握
    public void Process(G.GoodVersion p) { Enqueue(new C.Login { ... }); } // 发登录包
    public void Process(G.Disconnect p)  { Connected = false; }
    public void Process(S.Login p)       { /* 打印结果 */ }
}

// 主程序
Packet.IsClient = true;                  // ★ 关键: 告诉 Packet 类这是客户端, 影响序列化
var conn = new TestConnection(client);
conn.StartReceive();
conn.UpdateTimeOut();                    // ★ 关键: BaseConnection 构造没初始化超时, 不调会立即超时断开
for (int i = 0; i < 300; i++) { conn.Process(); Thread.Sleep(100); }
```

### 两个坑

1. **`Packet.IsClient = true` 必须设**：Packet 序列化区分客户端/服务端方向（`Packet.cs:16`）。不设的话包 ID 映射可能错位。
2. **`UpdateTimeOut()` 必须在连接后调**：`BaseConnection` 构造函数（`BaseConnection.cs:52`）设了 `TimeConnected` 但没调 `UpdateTimeOut()`，`TimeOutTime` 默认 `DateTime.MinValue`。第一次 `Process()`（`BaseConnection.cs:257`）检查 `Time.Now >= TimeOutTime` 立即 true → 发 Disconnect → 连接秒断。这是 BaseConnection 的一个小设计缺陷，Godot 客户端也要注意。

## 4. 验证结果

```
连接 127.0.0.1:7000 ...
TCP 已连接
[<-] Connected (服务端确认连接)
[->] Connected (客户端回握)
[<-] GoodVersion  *** 版本校验通过, 进入 Login 阶段 ***
[->] Login (尝试登录 test@test.com / test)
[<-] (未处理包) Ping
[<-] S.Login 结果: BadPassword
[<-] Disconnect  *** 被断开: TimedOut ***
```

逐行解读：

| 包 | 含义 |
|---|---|
| `Connected` ←/→ | TCP 握手完成，服务端确认连接，客户端回握 |
| `GoodVersion` ← | **版本流程通过**，进入 Login 阶段（CheckVersion=False 跳过校验） |
| `Login` → | 客户端发登录请求（test@test.com / test） |
| `Ping` ← | 服务端心跳（我们没实现 Process(Ping) 回复，所以显示"未处理包"） |
| `S.Login: BadPassword` ← | **服务端真正处理了登录**，查了账号库，返回"密码错误"（账号不存在，业务逻辑正常响应） |
| `Disconnect: TimedOut` ← | 没回 Ping 导致超时断开（预期行为） |

**关键证据**：`S.Login 结果: BadPassword` 证明服务端的**业务逻辑层**（不只是网络层）正常工作——它接收了登录包、查询了账号数据库、返回了业务结果。整条链路（TCP → packet 反序列化 → SConnection.Process → 登录逻辑 → 账号库查询 → 回包）全部打通。

## 5. 关掉版本校验的方法

在服务端工作目录建 `Server.ini`：

```ini
[Network]
IPAddress=127.0.0.1
Port=7000

[System]
CheckVersion=False
MapPath=./Map/
```

> `ConfigReader`（`LibraryCore/ConfigReader.cs`）读 ini 时按 `[Section]` + `Key=Value` 匹配，缺的 key 用代码默认值。所以只需写要改的项。
>
> 以后 Godot 客户端 dll 固定后，可以算它的 SHA256 填到 `Config.ClientHash`，再开 `CheckVersion=True`。但开发阶段关掉更方便。
