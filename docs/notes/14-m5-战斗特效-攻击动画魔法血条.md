## 1. M5 的数据链路

```
服务端战斗逻辑 (PlayerObject.Attack → AttackLocation 只打前方一格)
  → S.ObjectAttack    (攻击者 + 方向 + 被击者 TargetID, 广播含自己)
  → S.ObjectStruck    (被击者被击退到新位置, 广播)
  → S.HealthChanged   (掉血, 延迟 ~300ms, Miss/Block/Critical 标记)
  → S.DataObjectMonster / S.DataObjectHealthMana / S.DataObjectMaxHealthMana
                     (血量的权威值: 进游戏时批量 + 战斗后同步)
  → S.StatsUpdate    (玩家 MaxHealth/MaxMana 来源)
  → S.ObjectDied      (死亡, 客户端播 Die 动画后延迟移除)
```

客户端战斗动画映射（简化，不做技能分支）：

| 事件 | 客户端动作 |
|---|---|
| `ObjectAttack(自己)` | 玩家播 `Combat3`（`GetAttackAnimation` 对 Warrior/None 的默认攻击，帧表 start 720×6 帧） |
| `ObjectAttack(其他)` | 该对象播 `Combat1`（DefaultMonster start 160×6 帧） |
| `ObjectAttack.TargetID` | 被击者播 `Struck`（怪 2 帧 / 玩家 Struck） |
| `ObjectStruck` | 对象位移到新格 + 播 `Struck` |
| `HealthChanged` | 扣血（Miss/Block 不扣）+ 亮血条 |
| `ObjectMagic` | 施法者播攻击动画 + 目标格处 `EffectNode` 魔法光效 |
| `ObjectDied` | 播 `Die`（10 帧）→ 1.2 秒后 `QueueFree` |

## 2. 血量系统的数据来源（血条是谁喂的）

血条自绘矩形（不用原客户端 Interface.Zl 帧）：怪物 40×5、玩家 48×6，黑底 + 绿(>50%)/黄(>25%)/红填充条，挂在头顶上方。数据按 ObjectID 匹配：

| 包 | 谁吃 | 字段 |
|---|---|---|
| `DataObjectMonster` | 视野内怪物（进游戏批量 ~22 个） | `Health` + `Stats[Stat.Health]`=MaxHealth |
| `DataObjectHealthMana` | 玩家/怪物血量权威值 | `Health/Mana/Dead` |
| `DataObjectMaxHealthMana` | MaxHealth/MaxMana | `MaxHealth/MaxMana` |
| `StatsUpdate` | **玩家** MaxHealth/MaxMana | `Stats[Stat.Health/Mana]` |
| `HealthChanged` | 增量扣血（`CurrentHP += Change`） | `Change/Miss/Block/Critical` |

调试中发现并补上：玩家 `MaxHealth` 一直为 0（血条画不出）——`StatsUpdate` 之前是"未处理包"。加事件处理把 `Stats[Stat.Health]` 写入 `PlayerRenderer.MaxHealth`。

| 文件 | 改动 |

| `Scripts/PlayerRenderer.cs` | +HP 字段；+`_oneShotAnim` 一次性动画机制；+`PlayCombat/PlayStruck/PlayDie`；`_Draw` 画玩家血条 |
| `Scripts/EffectNode.cs` | **新建**：Node2D 画 Magic.Zl 指定帧，500ms 自删，位置经 `ComputeObjectScreenPos` 公式（相机跟随玩家） |
| `Scripts/GameScene.cs` | 订阅/退订/排空全部战斗事件；+`OnObjectAttack/ObjectMagic/HealthChanged/DataObjectHealthMana/MaxHealthMana/DataObjectMonsterInfo/ObjectStruck/ObjectDied/StatsUpdate` 处理器；+`SpawnEffectAt/ComputeObjectScreenPos` |

一次性动画的帧推进：`FrameStartMs` 在 `SetAnimation` 时重置，`_Process` 按帧表 `Delays` 逐帧推进（Combat3 = 6 帧 × 100ms = 600ms），播完（`now-FrameStartMs >= Sum`）回 Standing；Die 且 Dead 时保留最后一帧。Struck/Combat 被打断可被新动画覆盖（连击正常）。

## 4. 端到端验证（自动攻击调试，已删除）

为验证"不造假包"，临时加了一个自动攻击状态机：进游戏 2 秒后找最近怪物（曼哈顿距离）→ 逐格 `C.Move` 等回包确认 → 站在怪物**正前方一格**（服务端 `AttackLocation` 只打前方一格）→ 朝怪物发 `C.Attack`×3（间隔 1100ms > 攻击冷却 800ms）→ 收到 `ObjectAttack` 回包后 150ms 截图（动画播放中）。

**验证结果**：

```

[DBG] 就位: 玩家=(156,231) 目标=(155,230) 方向=UpLeft
[DBG] 攻击#1 → PlayCombat anim=Combat3 start=3602
[DBG] 攻击#2 → 截图时 玩家动画: Combat3 f=1 (startMs=5100, elapsed=150ms)
[DBG] HP: Pig(340) HP=13/15 bar=True dead=False   ← 被攻击 2 次掉 2 血
[DBG] HP: ... 15 个怪物全部 bar=True, NPC 全 bar=False
```

- 入队统计：14×ObjectAttack、8×ObjectStruck、17×HealthChanged、17×DataObjectHealthMana（服务端还广播了 `CombatTime`/`ObjectStruck`——`ObjectStruck` 已处理，`CombatTime` 是战斗计时提示，M5 范围外）
- 截图视觉（inspect_image）：① 玩家**攻击姿态**（双脚分开、身体前倾、挥棍）✓ ② 全屏怪物/玩家头顶**绿色血条** ✓ ③ 多只怪物**倒地尸体**（Die 动画 + 延迟移除）✓ ④ 玩家头顶上方 3 个**蓝色放射状魔法光效**（Magic.Zl 帧 0，EffectNode 渲染路径实测）✓
- 怪物受击后仰（Struck）在战斗截图中可见

**一个真实的时序坑**：截图若在"发出 C.Attack 后 120ms"，常常拍到 Standing——因为服务端 `ObjectAttack` 回包延迟不定（实测 30ms~600ms），动画从**回包到达**才开始。修正：截图时机改为"收到 `ObjectAttack` 回包后 150ms"，稳定捕获 Combat3 第 1 帧。

## 5. 说明与局限

- **魔法特效未走真实链路**：测试地图（出生点农场）的怪全是近战，服务端从不发 `ObjectMagic`。`OnObjectMagic` 处理器 + `EffectNode` 已按协议写完，渲染路径用临时定时 spawn 实测（蓝色光效正确画出）；施法者动画（怪 Combat / 玩家 Combat）逻辑与 ObjectAttack 同链路。等有法师怪/玩家施法的地图即可自然触发。
- 玩家血条：`StatsUpdate` 给 MaxHealth=52，`DataObjectHealthMana` 同步当前 HP，被怪打会扣（实测 52→34）。
- 原客户端还有 `ObjectStruck` 附带的效果（被击退音效、`NextActionTime` 卡顿）——我们只做位移 + 动画。
- `CombatTime`、`ObjectRangeAttack`、`ObjectMining`、`DataObjectPlayer`（其他玩家外观）仍为 M5 范围外未处理包。
