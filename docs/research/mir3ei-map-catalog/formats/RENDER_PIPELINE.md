# 渲染管线与验证 — 从素材到 minimap 图鉴

> 本文串联 FORMAT_WIL_WIX / FORMAT_ZL / FORMAT_MAP 三篇,给出**可运行的完整渲染链路**与**正确性验证方法**。所有脚本在本目录 `tools/`。

## 1. 管线总览

```
.map ──read_back_positions──▶ back 层 (file, frame) 表
                                  │
                                  ▼
                          文件字节 → 库名 (KRO/SUBDIRS)
                                  │
                                  ▼
                    WIL/Zl 库 ──▶ 帧解码 (RLE565 / DXT1 / DXT5)
                                  │
                                  ▼
                    瓦片贴画布 (96×64 原始 → SCALE=8 → 12×8/格)
                                  │
                                  ▼
                         566 张全尺寸渲染图 (views/)
```

## 2. 各步要点

1. **读 map**:`read_back_positions`(`tools/mir3ei_render.py`)—— 头 22B + W/H@22 + back 层 3B/条 + 13/14B 单元格探测。
2. **库映射**:`krname(file)` — 0–13 基础库、15–71 主题子目录(完整表见 FORMAT_WIL_WIX §4)。**`Wood/T5c`/`Forest/T5c` 需重命名为 `Wood/Tiles5c`/`Forest/tiles5c` 才能打开。**
3. **帧有效性与解码**:WIX 有效帧规则(28 ≤ offs < len)+ RLE 行解码(WIL);meta 块解析 + DXT1/DXT5(Zl)。
4. **瓦片合成**:back 层一格 96×64,按 alpha 合成到底色 `RGB(40,40,40)` 画布;缩到 12×8/格。
5. **输出**:每图一个 PNG(`views/{mapname}.png`)。

## 3. 家族接片图(contact/)

`tools/make_contact.py` — 按家族前缀把 566 张缩略成 8 列 × 160×90 网格、左下角黄字点名:

```
num / other / kt / E / DM / B / D00xx … D90xx  (34 家族)
```

接片图**不可从素材直接再生**,是人工鉴定辅助产物,已版本化在 `contact/`。

## 4. 指纹匹配(旧版 → 新版锚定)

数据在 `data/`:`mir3ei_fp.json`(旧版 566 张)、`zircon_fp.json`(新版 244 张)、`mir3ei_bestmatch.json`(每张 top-3)。

- **指纹** = 地图 back 层 `(库:帧)` 使用频率直方图(归一化)
- **相似度** = 两直方图重叠度(Σ min(a_i, b_i));1.0 = 瓦片构成完全一致
- **判读经验**:
  - `sim = 1.0` → 锚定同图(跨版本命名不同也成立):D1101→D1001 潘夜神殿、D15011→D12011 真天宫、D8001→D404 蚂蚁洞、D900→D1401 幽灵船、D12xx 全系、num 41–44→南部沙漠等
  - `sim ≥ 0.85` → 可靠锚定(阈值);如 8→D4003 0.863、81→D3400 0.849
  - `sim ≈ 0.40` → **噪声底** = 新版已精简该地图,无对应(约 392 张)
  - 小地图(建筑内部/kt 家族)的 0.9+ 匹配是单瓦片主导分布的巧合,**以视觉鉴定为准,大图以指纹为准**

## 5. 渲染器正确性验证(A/B)

结论:**旧 WIL 渲染 ≡ 新版 Zl 渲染(同地图同布局同画质,仅量化噪声差异)**。验证方法:

1. 同一张地图,分别用旧 WIL 管线与新版 Zl 管线渲染(如 D1101 矿洞/D1001 潘夜神殿)
2. 逐像素对比:MAE 14–45(±1 级量化差)、exact 像素比 0.32–0.71 —— 符合 DXT5 有损 vs RLE565 的预期噪声量级
3. 帧 0 均值核对:旧 `(42.5, 176.1, 174.8)` ≡ 新 `(43, 178, 179)`

### 5.1 曾踩的渲染 bug(全灰现象)

| bug | 表现 | 修复 |
|---|---|---|
| KROrder 缺 15/17 映射 | 主题子目录库解析为 None,瓦片全跳 | 补全 KRO 13 条 + SUBDIRS 57 条完整映射 |
| DXT5 位布局按连续 16B 解 | 颜色索引错位,画面全灰 | c0/c1@8–9、2bpp 索引@12–15(见 FORMAT_ZL §3.3) |
| WIX 首 Int32 当 count | 整库帧错位 | 读 meta 块到内存流再解析 |
| 未判有效帧 | 别名重映射索引读到垃圾 | `28 ≤ offs[i] < len(d)` 过滤 |

**教训**:出现"大面积全灰/全空"先怀疑库映射表与位布局,不要怀疑数据本身。

## 6. 图鉴重建全流程

```bash
# 1. 重新渲染 566 张(需原始客户端,覆盖 views/)
python3 tools/mir3ei_render.py

# 2. 重建 34 张家族接片图
python3 tools/make_contact.py

# 3. 重新生成单文件 HTML 图鉴(内嵌缩略图 + 接片,自包含 6.2MB)
python3 build_report.py
```

HTML 内嵌策略:566 张缩略图 JPEG 300px/q78(约 6–13KB/张)base64 内嵌,接片 900px/q80;总 634 图 0 broken、34 家族、566 明细行。
