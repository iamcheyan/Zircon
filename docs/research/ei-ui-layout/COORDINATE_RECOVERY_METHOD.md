# EI 3.0 UI 坐标恢复方法

本文记录本项目恢复原版 800×600 UI 坐标的统一方法。目标是从 `Mir3.exe` 和原版
`Data/*.wil` 中得到可复核的坐标、尺寸、资源帧和命中区域；预览器中的框线只是这些
证据的可视化，不是手工校准结果。

## 证据优先级

1. **一级：原版二进制静态证据**
   - `SetRect` 的立即数、寄存器表达式和窗口构造参数。
   - `PtInRect` 调用前使用的 `RECT`，可恢复真实命中矩形的构造路径。
   - WIL 资源选择器、Frame 编号、宽高读取和绘制调用。
2. **一级：原版资源证据**
   - WIL 头部中的帧宽、高、偏移和透明像素边界。
   - 资源图像只能证明资源本身的矩形，不能自动证明窗口容器尺寸。
3. **二级：原版服务器/配置交叉证据**
   - 例如 `Mud3/Envir/MiniMap.txt` 对地图名与 MMap/FMMap 帧的对应关系。
   - 可解释资源索引，但不能替代客户端绘制入口。
4. **候选：公开源码、现代 Zircon 或截图**
   - 只能用于提出名称或结构假设，不能覆盖 EI 二进制已经观察到的值。

## 坐标恢复链

### 1. 固定窗口

原版主初始化入口 `0x00427600` 依次创建窗口包装对象。每个调用序列提供：

```text
窗口 ID → wrapper → GameInter Frame → x,y,width,height → 是否可移动
```

这些参数是窗口对象的构造/容器矩形，直接记录在
`window-initialization-evidence.json`。例如人物状态窗口是 Frame 200、容器
`244×328`，背包是 Frame 250、容器 `284×324`。不能用 WIL Frame 的原始尺寸替换
这些显式容器尺寸，因为资源尺寸和窗口尺寸在 EI 中经常不同。

### 2. 窗口内部控件

控件构造器 `0x00417550` 保存位置，并读取选定 WIL Frame 的宽高后调用
`USER32.SetRect`（IAT `0x004762B0`）。因此控件命中矩形的可复现公式是：

```text
控件局部矩形 = (position_x, position_y,
                selected_frame.width, selected_frame.height)
屏幕矩形     = 窗口原点 + 控件局部矩形
```

鼠标路径 `0x00417780/0x004177C0/0x004177F0` 使用 `PtInRect` IAT
`0x004762B4` 检查该矩形。只有当窗口原点也由 EI 构造、位置分发或明确的固定
坐标证据给出时，结果才能升级为屏幕绝对坐标；否则必须保留为
`window-relative`。

### 3. 主 HUD

主 HUD 的静态底板是 `GameInter.wil Frame 50`，原版 800×600 视口中的屏幕原点
为 `(0,465)`，尺寸 `800×136`。动态资源不能按 Frame 编号简单从上到下堆叠，当前
已经从 `0x00429740` 记录出局部顺序：动态状态帧 → Frame 62 → Frame 60 → Frame 61
→ Frame 63 → 经验百分比文字。Frame 60/61/63 的覆盖层目前在预览器中标作
“静态候选”，因为运行时血量、魔法和经验比例仍需注入。

### 4. 地图

地图资源选择和 UI 目标必须分开：

```text
map_id >= 1000  → FMMap.wil，frame = map_id - 1000
map_id <  1000  → MMap.wil， frame = map_id
```

客户端 `0x0043D780` 证明选择关系；`0x0043D551` 对 `owner+0x2C0` 设置的固定
目标矩形是 `(672,0)-(800,128)`。这是原版小地图目标，不等于 MMap/FMMap 源图
尺寸，也不等于边框资源。`0x0043DA80 → 0x004542F0` 负责源/视图变换和合成，
所以预览器必须同时标出源图、目标矩形、边框候选和“尚未解析”的标记层。

## 为什么不需要手动拖动

手动拖动只能拟合一张截图，不能恢复：窗口移动后的相对关系、透明像素边界、
不同状态的 Frame、控件命中区域和动态绘制顺序。静态逆向可以直接得到这些
结构化数据；手动校准只应作为最后的截图差异验证，而不是坐标来源。

## 当前实现约束

- `layout.json` 是统一预览输入，生成方式是 `Tools/reverse-engineering/enrich_mir3_layout_evidence.py`。
- `Tools/web/wilviewer.py /ui` 固定显示 800×600，并把资源矩形、窗口容器矩形、控件
  命中矩形分层显示。
- 每个未闭合的语义都保留 `candidate` 或 `pending`，不能为了画面好看写成已确认。
- 原版文件必须保持只读；所有结论写入 `docs/research/ei-ui-layout/*.json`、
  `RESEARCH_LOG.md` 和对应专项证据文件。

## 下一步闭合顺序

1. 找到窗口可见列表最终消费它的绘制入口，确定跨窗口绘制顺序。
2. 对地图边框/覆盖层、全图入口和地图标记继续做调用链闭合。
3. 对状态、背包、技能、任务、商店和 NPC 窗口补齐运行时字段与文字绘制顺序。
4. 将每个闭合结论接入预览器，再用截图差异做验证；差异结果不能反过来修改一级坐标。
