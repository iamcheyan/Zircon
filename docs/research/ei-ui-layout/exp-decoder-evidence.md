# EI `*.exp` 客户端解码证据

更新时间：2026-08-09

## 已实现

`Tools/content/decode_mir3_exp.py` 复现了 `Mir3.exe` 的 `0x004525F0` 例程。它适用于
供应的 EI 3.0 `Magic.exp` 和 `MExplain.exp`，输出到 `/tmp` 或用户指定目录，
不改写原始客户端文件。

示例：

```bash
python3 Tools/content/decode_mir3_exp.py \
  /home/tetsuya/NAS/TMP/EI传奇3.0客户端/Magic.exp \
  /home/tetsuya/NAS/TMP/EI传奇3.0客户端/MExplain.exp \
  --out-dir /tmp/mir3-exp-decoded
```

## 算法对应关系

| 逻辑 | 原版地址 | 结论 |
|---|---:|---|
| 初始化解码上下文 | `0x00452580` | 写入全局 `0x9135B8` / `0x9135BC` 两个 DWORD |
| 文件/资源包装 | `0x0046926D` | 接收 `/%s` 与文件名 |
| 头部长度 | `0x004525F0` | `raw_u32[0] XOR caller-provided KEY1` |
| 头部校验 | `0x004525F0` | `KEY2 XOR Σ((payload[i]+1)×i)` |
| 正文解码 | `0x0045267F–0x0045269A` | 用头部第 4/3/2/1 字节作为四轮递增 XOR 掩码 |

供应的 EI 文件验证结果：

| 文件 | 原始大小 | 解码总长度 | 正文长度 | 校验 |
|---|---:|---:|---:|---|
| `Magic.exp` | 14,735 | 14,735 | 14,727 | 通过；`KEY1=0x0992007F` |
| `MExplain.exp` | 285 | 285 | 277 | 通过；`KEY1=0x9BAA38ED` |

解码后的文本以 GB18030 为主要编码，`Magic.exp` 开头可见 `#3` 记录标记；这已经
证明文件不是不可解析的随机密文，而是客户端自有的带校验与正文变换的数据格式。
两个文件的 `KEY1` 不同，不能把一个文件的种子直接套到另一个文件；工具默认从
供应文件长度得到候选并用 `KEY2` 校验确认，也支持 `--key1` 显式覆盖。

## 仍待恢复的内容

解码算法已确认，但记录语法尚未全部确认。下一步要从 `0x00439150` 后续读取点、
`0x00439220` 的窗口字段和 `0x0043A440` 输入/刷新路径，恢复：

- `#1/#2/#3` 各段的记录边界；
- 技能 ID、技能名、等级/熟练度、MP、威力等字段；
- 八个技能分类页签与记录段的映射；
- 客户端 `Magic.exp` 与 Mud3 `Envir/magic.dat` 的逐条对应关系。

在这些字段完成前，不能把解码文本中的每个数字直接命名为技能等级或威力。
