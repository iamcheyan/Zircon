01 / Executive brief

先给结论：基线不是“少几个功能”，而是两套时代的服务器哲学。

参考包呈现的是一个以地图、刷怪、NPC 配置和三段式网关为中心的老式部署；Zircon 当前则已经是数据驱动、强协议、多人社交和大量后期系统叠加的服务端。裁剪时应以“基线保留 / 后期剔除 / 依赖待核实”三色台账推进。

02 / Context

时代脉络

公开资料对年份有细小差异：WEMADE 年报把《传奇3》商业化起点记为 2003 年；中文玩家史料按中国大陆代理和版本更新记录展开；公开百科则常写作 2004 年发行。这里把它们作为“版本谱系背景”，不拿它们替代本地包证据。

1998

Mir 系列的早期根系

公开历史资料将《The Legend of Mir: The Three Heroes》列为系列早期作品，形成等距 2D、三职业与刷怪升级等核心范式。

2000–01

WEMADE 与 Mir 2 的商业化扩张

WEMADE 官方回顾称，2000 年由小团队推进 Mir 2；公司年报记载 Mir 2 于 2001 年 3 月商业化。传奇类 MMORPG 的服务器、网关和地图数据思路在这一时期成熟。

2003

中国大陆《传奇3》代理与早期版本

玩家史料记录 2003 年 3 月签约、4–7 月测试、8 月收费，并在同年推出“风云再起沙巴克”和“苏醒的神舰”等版本节点。

2004+

地图、坐骑、地城与任务系统继续叠加

公开资料对 Legend of Mir 3 的概括提到更大的地图、更多自定义、坐骑、地城和怪物；这与当前 Zircon 中大量后期数据模型相互印证，但具体包版本仍需逐项追溯。

2026

Zircon：保留原服务端逻辑，重写跨平台客户端

当前仓库以 ServerCore / ServerLibrary / LibraryCore 原样复用为主，Godot 重写渲染、UI 与输入，并建立了地图探测、数据库文档、BotRunner、资产查看器等研究工具链。

可复核的关键配置

文件观察到的事实对裁剪的意义
Mir3Server/Loginsvr/Logsrv.iniLoginServer 监听 5600，并指向 GatePort 5500；有注册、修改密码、找回密码等开关。账号入口是独立服务，不等于当前 ServerCore 的单一 TCP 入口。
Mir3Server/DBsvr/DBsrv.iniDBsvr 监听 6000，GatePort 5100，读取 Mapinfo.txt，启用新用户与删用户。账号/角色/游戏数据职责被拆开，数据服务是基线的一部分。
Mir3Server/RunGate/RunGate.ini对外 GatePort 7200，包大小、连接数、IP 限流、NPC/GM 过滤均可配置。网关和安全过滤属于部署边界，不应在功能裁剪初期误删。
Envir/Mapinfo.txt地图行包含 DAY、SAFE、HORSE、FIGHT、NORECALL 等规则标志；StartPoint.txt 给出出生点。地图规则是服务端世界模型的核心，可作为“老版本最小集”锚点。

06 / Architecture

两种架构的对应关系

参考包：多进程 + 文件配置 + 网关

登陆器 / Mir3.exe │ ▼ Loginsvr :5600 ──► DBsvr :6000 │ │ └──────► RunGate :7200 ◄── 3Gates │ ▼ Envir + Map + 运行时目录

当前开发：共享协议 + 无头服务端 + Godot

GodotClient ── TCP :7000 ──► ServerCore │ │ ├─ RenderingCore / Zl / Map ├─ ServerLibrary ├─ UI / 输入 / 客户端状态 └─ LibraryCore / packets / DB └─ BotRunner（测试客户端） 目标：先恢复可玩的基线，再决定后期层的去留。

重要边界

当前 README 的复用策略是“ServerLibrary、LibraryCore、ServerCore 原样复用；Godot 重写客户端”。这不等于当前服务端已经是 20 年后的官方版本，也不等于所有当前 packet 都必须保留。真正的裁剪对象应分为：数据表/枚举、服务端规则、协议包、客户端 UI、资产、运维工具六层逐项处理。

07 / Cutting plan

建议的裁剪工作台

不要先删代码；先建立一份可回滚的功能谱系。每个候选系统都要回答“它是否在基线包有证据、它被哪些 packet/数据库表/UI 引用、删掉后登录/地图/战斗是否仍闭合”。
